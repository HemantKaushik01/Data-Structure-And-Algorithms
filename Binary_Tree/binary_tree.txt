================================================================================
                                THE BINARY TREE
================================================================================

A Binary Tree is one of the most fundamental and versatile non-linear data 
structures in computer science. Unlike arrays, linked lists, stacks, and queues, 
which store data sequentially, a binary tree stores data hierarchically.

This document covers the comprehensive theory of Binary Trees: what they are, 
why we use them, where they are applied, real-life examples, and visual 
architectural diagrams.

--------------------------------------------------------------------------------
1. WHAT IS A BINARY TREE?
--------------------------------------------------------------------------------

A Binary Tree is a hierarchical data structure in which each node has at most 
two children, referred to as the left child and the right child.

Represented mathematically, a Binary Tree T is either empty or consists of:
- A distinguished node called the Root.
- Two disjoint binary trees called the Left Subtree and the Right Subtree.

+------------------------------------------------------------------------------+
| A. The Anatomy of a Node                                                     |
+------------------------------------------------------------------------------+
Each node in a binary tree typically contains three fields:
1. Data / Value: The actual data stored in the node.
2. Left Pointer: A reference/link to the left child node.
3. Right Pointer: A reference/link to the right child node.

                          +-----------------------+
                          |      Node (Data)      |
                          +-----------+-----------+
                          | Left Link | Right Link|
                          +-----+-----+-----+-----+
                                |           |
                                v           v
                          Left Child     Right Child


+------------------------------------------------------------------------------+
| B. Binary Tree Architecture & Terminology Diagram                            |
+------------------------------------------------------------------------------+

                          [ Root Node (A) ]           <-- Level 0 (Depth 0)
                               /     \
                              /       \
                             /         \
                     [ Node (B) ]     [ Node (C) ]    <-- Level 1 (Depth 1)
                       /      \          /     \
                      /        \        /       \
               [ Node (D) ]  [ Node (E) ]        [ Node (F) ] <-- Level 2 (Depth 2)
                                /                  /
                               /                  /
                        [ Node (G) ]       [ Node (H) ]   <-- Level 3 (Depth 3)

Key Terms:
- Root: The topmost node of a tree (Node A). It has no parent.
- Parent: A node that has branches leading to other nodes. (e.g., A is the parent of B and C).
- Child: A node directly connected to another node when moving away from the Root. (e.g., B and C are children of A).
- Leaf Node (External Node): A node with no children (Nodes D, G, and H).
- Internal Node: A node with at least one child (Nodes A, B, C, E, and F).
- Edge: The physical link or transition between a parent and its child node.
- Path: A sequence of nodes and edges connecting a node to a descendant.
- Depth of a Node: The number of edges from the root to the node. 
  * Depth of Root (A) = 0
  * Depth of Node (G) = 3
- Height of a Node: The number of edges on the longest path from the node to a leaf.
  * Height of Node (B) = 2 (Path: B -> E -> G)
  * Height of Leaf (D) = 0
- Height of the Tree: The height of the Root node. In the diagram above, the height of the tree is 3.
- Subtree: Any node can be viewed as the root of a smaller binary tree.
  * Left Subtree is rooted at B.
  * Right Subtree is rooted at C.

2. MATHEMATICAL PROPERTIES & FORMULAS
--------------------------------------------------------------------------------

Binary trees possess several key mathematical properties. These properties help 
us calculate heights, count nodes, check balance, and optimize tree structures.

NOTE: Two conventions exist for measuring height:
- Convention A (0-Indexed, Default): A single-node tree has a height of 0.
- Convention B (1-Indexed): A single-node tree has a height of 1.
Below, we use Convention A (Height of single node = 0), but also provide the 
equivalent formulas for Convention B.

+------------------------------------------------------------------------------+
| A. Node Count vs. Height (h)                                                 |
+------------------------------------------------------------------------------+
For a binary tree of height 'h':

1. Maximum Number of Nodes (N_max):
   Occurs in a Perfect Binary Tree.
   * Convention A (height 0): N_max = 2^(h + 1) - 1
   * Convention B (height 1): N_max = 2^h - 1
   
   Example: If height h = 3 (Convention A), N_max = 2^(3+1) - 1 = 15 nodes.

2. Minimum Number of Nodes (N_min):
   Occurs in a Skewed/Degenerate Tree (behaves like a linked list).
   * Convention A (height 0): N_min = h + 1
   * Convention B (height 1): N_min = h
   
   Example: If height h = 3 (Convention A), N_min = 3 + 1 = 4 nodes.

3. Maximum Nodes at any Level 'i':
   At level i (where Root is Level 0), the maximum number of nodes is:
   * Max Nodes at Level i = 2^i
   
   Example:
   - Level 0 (Root)  : 2^0 = 1 node
   - Level 1         : 2^1 = 2 nodes
   - Level 2         : 2^2 = 4 nodes
   - Level 3         : 2^3 = 8 nodes

+------------------------------------------------------------------------------+
| B. Height (h) vs. Node Count (N)                                             |
+------------------------------------------------------------------------------+
For a binary tree with 'N' nodes:

1. Minimum Height (h_min):
   Occurs when the tree is as balanced and full as possible (e.g., Perfect/Complete Tree).
   * Convention A (height 0): h_min = floor(log2(N))
   * Convention B (height 1): h_min = floor(log2(N)) + 1
   
   Example: If N = 10 nodes (Convention A):
            h_min = floor(log2(10)) = floor(3.32) = 3.

2. Maximum Height (h_max):
   Occurs in a completely Skewed Tree.
   * Convention A (height 0): h_max = N - 1
   * Convention B (height 1): h_max = N
   
   Example: If N = 10 nodes (Convention A), h_max = 10 - 1 = 9.

+------------------------------------------------------------------------------+
| C. Leaf Nodes vs. Degree-2 Nodes                                             |
+------------------------------------------------------------------------------+
In any non-empty binary tree, let:
- L   = Number of Leaf nodes (Degree 0)
- N_2 = Number of Internal nodes with exactly two children (Degree 2)

There is a constant, invariant relationship between them:
* L = N_2 + 1  (The number of leaves is always exactly 1 more than the number of 
               nodes with 2 children).

Example:
In a Perfect Tree with 7 nodes:
         (A)           - Nodes with 2 children (Degree 2) = 3 (A, B, C)
        /   \          - Leaf nodes (Degree 0) = 4 (D, E, F, G)
      (B)   (C)        - L = N_2 + 1 => 4 = 3 + 1. (Always holds true!)
     /   \ /   \
    (D) (E)(F) (G)

+------------------------------------------------------------------------------+
| D. Perfect & Complete Binary Tree Properties                                 |
+------------------------------------------------------------------------------+
For a Perfect Binary Tree of height 'h' (Convention A):
- Total Nodes (N)          = 2^(h + 1) - 1
- Number of Leaf Nodes (L)  = 2^h
- Internal Nodes (I)        = 2^h - 1  (or N - L)

+------------------------------------------------------------------------------+
| E. Array Representation Formulas (Zero-Based Indexing)                       |
+------------------------------------------------------------------------------+
If a Complete Binary Tree is stored in a sequential Array (common in Heaps), 
for any node stored at index 'i' (Root is at index 0):

- Left Child Index          = 2 * i + 1
- Right Child Index         = 2 * i + 2
- Parent Index              = floor((i - 1) / 2)   (where i > 0)

Example:
If node 'B' is at index 1:
- Left child is at index: 2 * 1 + 1 = 3
- Right child is at index: 2 * 1 + 2 = 4
- Parent is at index: floor((1 - 1) / 2) = 0 (Root)

3. WHY DO WE USE BINARY TREES?
--------------------------------------------------------------------------------

Why not just use Arrays, Linked Lists, or Hash Tables? Each of those linear structures 
has trade-offs:
- Arrays: Fast access (O(1)) but slow insertions/deletions (O(N)) because elements must be shifted.
- Linked Lists: Fast insertions/deletions (O(1) once at the position) but slow search/access (O(N)) because we must traverse sequentially.
- Hash Tables: Fast average operations (O(1)) but do not maintain order, making sorted traversals or range queries extremely inefficient.

Binary Trees (specifically balanced variants) offer the best of both worlds:

1. Hierarchical Representation: 
   Perfect for storing data that naturally has a parent-child relationship (like folder directories).
   
2. Logarithmic Efficiency (O(log N)):
   In a balanced binary search tree, search, insertion, and deletion operations take logarithmic time, which is incredibly fast for large datasets.
   * For 1,000,000 items: 
     - Linear search takes up to 1,000,000 steps.
     - Binary tree search takes at most ~20 steps (log2(1,000,000) ≈ 19.93).

3. Dynamic Size:
   Unlike traditional arrays, binary trees can dynamically grow and shrink in memory. There is no need to pre-allocate memory or resize arrays.

4. Ordered Traversals:
   Trees allow you to traverse elements in sorted order effortlessly. For example, an In-Order traversal of a Binary Search Tree (BST) visits nodes in ascending order.

4. CLASSIFICATION & TYPES OF BINARY TREES
--------------------------------------------------------------------------------

+------------------------------------------------------------------------------+
| A. Full Binary Tree                                                          |
+------------------------------------------------------------------------------+
Every node has either 0 or 2 children. No node has exactly 1 child.

               (A)
              /   \
            (B)   (C)
           /   \
         (D)   (E)

+------------------------------------------------------------------------------+
| B. Complete Binary Tree                                                      |
+------------------------------------------------------------------------------+
All levels are completely filled except possibly the last level, which is 
filled from left to right.

               (A)
              /   \
            (B)   (C)
           /   \   /
         (D)   (E)(F)

+------------------------------------------------------------------------------+
| C. Perfect Binary Tree                                                       |
+------------------------------------------------------------------------------+
All internal nodes have exactly two children, and all leaf nodes are at the same level.

                (A)
              /     \
            (B)     (C)
           /   \   /   \
         (D)   (E)(F)  (G)

+------------------------------------------------------------------------------+
| D. Balanced Binary Tree                                                      |
+------------------------------------------------------------------------------+
A binary tree where the height of the left and right subtrees of any node 
differs by at most 1. This ensures O(log N) operations. Examples: AVL Tree, 
Red-Black Tree.

+------------------------------------------------------------------------------+
| E. Degenerate (Skewed) Binary Tree                                           |
+------------------------------------------------------------------------------+
A tree where every parent node has only one child. It essentially behaves 
like a singly linked list, degrading operations to O(N).

         (A)
        /
      (B)
     /
   (C)

5. WHERE ARE BINARY TREES USED? (APPLICATIONS)
--------------------------------------------------------------------------------

In computer science, binary trees are used under the hood in almost every major system:

1. Binary Search Trees (BST):
   - Used in database indexing (e.g., MySQL indexing using B-Trees/B+ Trees, which are generalized forms of BSTs) for rapid query search times.
   - Set and Map implementations in standard libraries (like `std::set` in C++ or `TreeMap` in Java, which use Red-Black trees).

2. Heap Trees (Priority Queues):
   - Min-Heaps and Max-Heaps are complete binary trees.
   - Used in Heap Sort, OS process scheduling (scheduling higher-priority tasks first), and graph algorithms like Dijkstra's Shortest Path.

3. Huffman Coding Tree:
   - Used in data compression algorithms (like JPEG and MP3 formats) to encode frequent characters with fewer bits.

4. Expression Trees:
   - Compilers use expression trees to parse, analyze, and evaluate mathematical and programming language statements.
   - For example, the expression `(3 + 5) * 2` is parsed as:
   
                   (*)
                  /   \
                (+)   (2)
               /   \
             (3)   (5)

5. Routing Tables:
   - High-bandwidth routers use IP routing trees (tries/trees) to quickly route internet traffic packets to their destinations.

6. REAL-LIFE ANALOGIES & EXAMPLES
--------------------------------------------------------------------------------

To visualize binary trees in the real world, consider these scenarios:

1. Ancestry / Family Trees:
   If you look backward in time, every biological person has exactly two biological parents. Your direct ancestors form a perfect binary tree:
   
                                  [ You ]
                                 /       \
                          [ Father ]   [ Mother ]
                           /     \       /     \
                         [GF]   [GM]   [GF]   [GM]

2. File System Directory Structure:
   Every folder can contain subfolders (children) or files (leaves). While this is a general tree, binary partitions are frequently used in file system indexes to locate paths extremely fast.

3. Sports Tournaments (Knockout/Bracket system):
   In a single-elimination tournament, the final match is the root node. The semifinal matches are its children, and the opening rounds are the leaf nodes. As teams compete, the "winner" moves up the tree:

                                [ Champion ]
                               /            \
                       [ Finalist 1 ]    [ Finalist 2 ]
                        /          \      /          \
                      [SF1]      [SF2]  [SF3]      [SF4]

4. Decision Making (Yes/No Decision Tree):
   A basic binary tree can model a sequence of binary choices (Yes or No).
   
                        Should I go outside?
                             /        \
                        [Yes]          [No]
                        /   \          /  \
                   Sunny?  Rainy?   Tired? Energized?

7. CORE BINARY TREE TRAVERSALS
--------------------------------------------------------------------------------

To process all nodes in a binary tree, we traverse them. There are two primary 
categories of traversal:

A. Depth-First Search (DFS):
   1. Pre-Order (Root -> Left -> Right):
      - Good for cloning or copying a tree.
   2. In-Order (Left -> Root -> Right):
      - Visits nodes in sorted ascending order in a Binary Search Tree (BST).
   3. Post-Order (Left -> Right -> Root):
      - Good for deleting a tree (you delete children before the parent).

B. Breadth-First Search (BFS):
   1. Level-Order:
      - Visits nodes level-by-level, from top to bottom, left to right.
